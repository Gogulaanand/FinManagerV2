# R1.2 Auth-Transition Safety

**Status:** implemented and locally verified on 2026-08-02
**Scope:** R1.2 of `FINMANAGER_PRODUCTION_READINESS_PLAN.md`

## Contract

Explicit sign-out is a data operation, not only an authentication operation:

1. Read the PowerSync upload-queue count and the active user's unresolved local failure count.
2. Allow the existing upload worker up to eight seconds to drain retryable work.
3. Sign out immediately only when both counts are zero.
4. Otherwise keep the session and local database, then offer retry, recovery export, or staying
   signed in.
5. Forced sign-out requires a successfully created recovery JSON plus explicit acknowledgement that
   local-only changes will be removed. Only then may the deliberate sign-out clear the database.

The recovery JSON reads the current local tables, so queued local rows are included. It remains an
export artifact, not a restore implementation; tested restore is R2.

## Auth-transition states

- **Authenticated, same user:** reconcile local ownership, connect PowerSync, then expose the
  session to consumers.
- **Transient null session:** remove the visible app session and disconnect PowerSync without
  clearing local rows, queue entries, failure records, or the remembered account.
- **Restored same user:** reconnect to the retained database. Serialized transitions prevent a late
  disconnect from winning over the restored connection.
- **Different user, clean database:** clear the previous account's downloaded cache, remember the
  incoming user, connect, then expose the new session.
- **Different user, unsafe database:** do not expose the incoming session or cached rows; keep the
  prior database intact, disconnect, clear the incoming local auth session, and show a safe error.
- **Deliberate clean/confirmed sign-out:** mark the next null-session transition as controlled clear,
  sign out through Supabase, then disconnect and clear.

Only counts and safe messages enter React/auth state. Financial rows, failure payloads, tokens, and
account identifiers are not logged or sent to telemetry.

## Implementation boundaries

- `packages/sync/src/sign-out.ts`: shared queue/failure snapshot, bounded wait, forced-discard guard,
  transient/deliberate disconnect policy, and account reconciliation.
- `packages/sync/src/export.ts`: platform-neutral local recovery artifact.
- Web/mobile providers: serialized Supabase-to-PowerSync transitions and the shared policy adapter.
- Web/mobile safe-sign-out components: platform-specific export and acknowledgement UI only.

R1.3's general synced/syncing/offline/action-required status surface remains out of scope.
